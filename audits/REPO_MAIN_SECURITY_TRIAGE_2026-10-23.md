## Material findings

- **90/100 default heads** contain a concealed VS Code `.vscode/tasks.json` shell task configured `runOn: folderOpen`, invoking a Node script disguised as an asset in `public/fonts/`. The corresponding referenced payload files were present at all 90 pinned heads. Someone is already merging security changes; do not issue bulk blind commits against stale heads.
- **Post-snapshot coordination note:** a subsequent read-only 100-repo head poll found Rezon `main` alone advanced to `052fbb7291cf5dd5527d4c6fde29f66718d60a57` (PR #110). The hidden-task pattern remained absent at that newer SHA. The pinned inventory deliberately keeps its original exact-head snapshot rather than silently replacing it.

## Immediate recommended order

1. Freeze installs, builds, and VS Code folder-open of still-affected default heads; notify other operators of the 90 affected repos and both variants.
2. Preserve pinned evidence (blob identifiers and repo heads below), investigate commit history and host execution telemetry, and assess/rotate exposed credentials where execution is plausible.
3. Use isolated, per-repo reviewed changes to remove malicious asset/tasks/autostart settings and any separate lifecycle hooks (`api.js` is a confirmed separate concern in `workbridgecommander`), and add static regression checks.
4. Run tests in a controlled environment **after removing every executable autostart/lifecycle hook**; confirm security containment before any feature work.
5. Coordinate merges centrally with per-repo exact-head comparison and explicit acceptance checks; do not blindly overwrite concurrent merges.
